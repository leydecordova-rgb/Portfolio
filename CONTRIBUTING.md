# Guía de contribución

¡Gracias por tu interés en contribuir a este proyecto! Para mantener un entorno ordenado y colaborativo, te pedimos que sigas estas pautas.

## Cómo reportar un error

Si encuentras un error (*bug*), por favor abre una nueva **Issue** incluyendo la siguiente información:

- **Título claro:** Una breve descripción del problema.
- **Pasos para reproducir:** Lista detallada de las acciones para replicar el error.
- **Comportamiento esperado:** Lo que debería suceder.
- **Comportamiento actual:** Lo que sucede realmente.
- **Capturas de pantalla o logs:** Si aplica, adjunta imágenes o mensajes de error.
- **Entorno:** Sistema operativo, navegador o versión de las herramientas utilizadas.

## Cómo proponer una mejora

Si tienes una idea para una nueva funcionalidad o mejora:

1. Revisa las **Issues** existentes para asegurarte de que la propuesta no haya sido enviada previamente.
2. Abre una **Issue** detallando la mejora sugerida, explicando la razón por la cual sería beneficiosa para el proyecto.
3. Discute la propuesta con el equipo antes de comenzar a trabajar en el código.

## Lista de verificación (Checklist) para Pull Requests

Antes de enviar tu **Pull Request (PR)**, asegúrate de cumplir con los siguientes puntos:

- [ ] El código sigue los estándares de estilo del proyecto.
- [ ] Se probaron los cambios localmente y no generan errores.
- [ ] Se agregaron o actualizaron las pruebas necesarias para la nueva funcionalidad o corrección.
- [ ] La documentación relacionada (como el `README.md`) fue actualizada si fue necesario.
- [ ] El título del PR es descriptivo y está vinculado a la **Issue** correspondiente.

### Pasos para hacerlo

1.	Haz un fork del repositorio.
2.	Crea una rama: `git checkout -b mejora/mi-cambio`
3.	Guarda tus cambios: `git commit -m "Describe tu cambio"`
4.	Sube la rama: `git push origin mejora/mi-cambio`
5.	Abre un Pull Request explicando que mejoraste.
